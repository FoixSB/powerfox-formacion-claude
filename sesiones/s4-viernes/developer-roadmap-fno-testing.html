03

Dataverse — el centro de todo

3 min

🗃️ Lo que Microsoft espera que sepas

Dataverse no es "una base de datos". Es el modelo de datos compartido + el motor de seguridad + el bus de eventos + la capa de extensibilidad — todo como SaaS.

  • Tablas, columnas, relaciones, choices
  • Role-based security a nivel de registro
  • Plug-ins (event handlers en C#)
  • Webhooks + Azure Service Bus
  • Custom API (tu RPC con lógica)
  • Virtual tables (datos externos sin replicar)

🛠️ Las 5 extensibilidades clave

  1. Plug-ins — código C# que corre en pre/post de operaciones Dataverse
  2. Webhooks + Service Bus — para integrar con sistemas externos asíncronamente
  3. Custom API — tus propias acciones expuestas en Web API
  4. Virtual tables — leer datos de SAP, Salesforce, etc. sin replicar
  5. Calculated columns + Business Rules — lógica declarativa sin código

Regla: empieza por Business Rules, escala a plug-in cuando topes con su límite.

05

F&O Testing — SysTest framework (caso especial)

5 min

⚠️ Heads up: Esta sección aplica si trabajáis con Dynamics 365 Finance & Operations (X++). En LitoClean esto puede no ser relevante, pero conviene saber que existe — si en el futuro hay un proyecto F&O, sabéis que el testing tiene su propio mundo.

🎯 Qué es SysTest

El framework de unit/component tests nativo de F&O. Vive dentro del unified developer experience de Power Platform — instalas las herramientas, abres Visual Studio, y los tests corren contra un sandbox cloud.

  • Lenguaje: X++
  • Editor: Visual Studio (no VS Code)
  • Ejecución: en el cloud contra sandbox
  • Aserciones: this.assertEquals, this.assertTrue, etc.
  • Atributo SysTestMethod marca métodos como tests
  • setup() corre antes de cada test

🧪 Test isolation — el atributo clave

El atributo SysTestTransaction controla cómo se aísla el test de los demás. Sin esto, un test que crea registros contamina los siguientes.

  • AutoRollback (default) — todo se hace en transacción, rollback al final
  • LegacyRollback — solo inserts trackeados
  • LegacyRollbackWithUpdateTracking — inserts + updates + deletes (más lento)
  • None — sin aislamiento (solo para debug)
// Ejemplo: test sobre el motor de totales de alquiler de coches (FleetManagement) [SysTestTransaction(TestTransactionMode::AutoRollback)] class FMUnitTestSample extends SysTestCase { public void setup() { FMDataHelper::main(null); // reset data } [SysTestMethod, Hookable(false)] public void testFMTotalsEngine() { FMRental rental = FMRental::find('000022'); FMTotalsEngine fmTotals = FMTotalsEngine::construct(); fmTotals.calculateRentalVehicleRate(rental); FMRentalTotal fmRentalTotal = fmTotals.totals(rental); this.assertEquals(expectedTotal, fmRentalTotal); } }

🔄 Flujo de ejecución: Build → Deploy model al cloud → Open Test Explorer → Run selected. Los tests corren en el cloud contra los datos del sandbox. No hay debug en el Test Explorer (limitación actual).

⚠️ Cuándo te interesa: Solo si el proyecto toca X++/F&O. Si vuestro stack es Power Platform "puro" (Canvas, MDA, Dataverse, Flows), Playwright para Power Platform es vuestra herramienta principal. SysTest entra en escena cuando hay módulos F&O custom.
