01

Qué es y para qué sirve

3 min

🎯 La frase de Microsoft

"Crowd-source and find templates and components within your organization easily."

El catalog es un repositorio gobernado de items reutilizables dentro de tu tenant. Los makers entran al catálogo desde Power Apps o Power Automate, ven una galería de tiles, instalan lo que necesitan, y arrancan con plantillas que ya están conectadas a tus sistemas y siguen tu theme corporativo.

📦 Los 3 tipos de items que aparecen

  • Publicados por tu organización — soluciones que un dev/maker interno publicó para que otros los usen
  • Publicados por partners aprobados — tu admin decide qué partners pueden publicar (ej. consultoras de confianza)
  • Publicados por Microsoft — AI prompts, Copilot app templates, dataflow templates, plantillas enterprise, PCF controls, plug-ins

💼 Por qué nos importa en LitoClean / Tema

Hoy: cada vez que un maker quiere reutilizar un componente que otro hizo, lo pide por Teams o email. Lo recibe como zip. Lo importa. Espera que la versión sea la última. Cero gobernanza.

  • El plug-in de validación de CIF que escribió Bladimir → catálogo
  • La canvas app de captura de partes de Foix → catálogo
  • El flow de notificación de aprobaciones → catálogo

Resultado: los siguientes 5 proyectos ya empiezan con base sólida.

📅 Estado: El catálogo está disponible en Power Apps y Power Automate. Microsoft sigue ampliando la oferta de templates en cada Release Wave. Es parte del fundamento estratégico de Power Platform 2026.

02

vs AppSource vs compartir solution.zip

3 min
Catalog ✓

Marketplace interno

  • Scope: tu tenant
  • Publican: tus equipos, partners aprobados, Microsoft
  • Versionado oficial
  • Install desde maker portal
  • Auditable
  • Roles: Submitter / Approver / Consumer
AppSource

Marketplace público

  • Scope: todos los tenants Microsoft
  • Publican: ISVs registrados
  • Versionado oficial
  • Install desde admin / maker
  • Cumple certificación Microsoft
  • No es para tu IP interna
Compartir zip ✗

El método clásico

  • Scope: quien recuerdes invitar
  • Publican: cualquiera con permiso de export
  • Sin versionado
  • Install: drag & drop manual
  • No auditable
  • Sin roles — caos puro

⚠️ El problema del método clásico: 6 meses después nadie sabe qué versión del componente tiene cada entorno. Cuando algo se rompe, no hay forma de saber si fue tu cambio o el zip que importó otro hace 3 meses.

04

Flujo: publicar y consumir

5 min

👨‍💻 Como Submitter (developer / maker)

  1. Empaqueta tu solución (con PAC CLI, XRMToolBox, Studio)
  2. Entra al Catalog manager app
  3. Submit del item con metadatos: nombre, descripción, versión, tags
  4. Esperas aprobación (depende de governance)
  5. Item aparece en el catálogo del tenant

🛠️ Como Approver (admin / DevOps)

  1. Recibes notificación de submit
  2. Revisas: ¿cumple naming? ¿tiene CLAUDE.md / docs? ¿auditoría de seguridad?
  3. Apruebas o rechazas con feedback
  4. Una vez aprobado, queda visible para todos los makers
  5. Versionas con cada update — el maker ve histórico

🎨 Como Consumer (maker)

  1. Entras a Power Apps maker portal
  2. Ves el catálogo con tiles
  3. Filtras: tipo de item, autor, tags
  4. Click en "Install" sobre el tile
  5. El item aparece en tu entorno listo para usar

👀 Como Auditor

  1. Vista del CoE Starter Kit conectada al catálogo
  2. Ves: quién publicó, quién instaló, en qué entornos
  3. Trazabilidad: si algo falla, sabes qué versión está donde
  4. Reportes mensuales de adopción

05

APIs: PAC CLI, SDK, Web API

5 min

Microsoft expone tres caminos para automatizar la publicación y consumo del catálogo. Elige el que encaje con tu pipeline:

⚡ PAC CLI (recomendado)

El más rápido para devs y DevOps. Instalas el CLI, te autenticas, y publicas con un comando.

# Listar items del catálogo pac catalog list # Submit de una solución como item pac catalog submit \ --path ./solution.zip \ --display-name "Litoclean Time Tracker" \ --description "Canvas app de partes de horas" # Install de un item pac catalog install \ --catalog-item-id "<guid>" \ --target-environment-id "<env-guid>"

🔧 SDK para .NET

Para apps cliente que necesitan integración profunda. Útil si construyes una herramienta interna que orquesta múltiples publicaciones.

// IOrganizationService + Catalog APIs var request = new SubmitCatalogItemRequest { Name = "litoclean_timetracker", Path = "./solution.zip", Version = "1.2.0" }; var response = service.Execute(request);

🌐 Dataverse Web API

Para clientes que no son .NET. Funciona desde PowerShell, Python, Node, lo que sea — es REST puro contra el endpoint del environment.

# PowerShell: listar items via Web API $response = Invoke-RestMethod ` -Uri "$envUrl/api/data/v9.2/catalogitems" ` -Headers @{ Authorization = "Bearer $token" } ` -Method GET

🤔 ¿Cuál usar?

  • Dev / DevOps en CI/CD → PAC CLI
  • App custom con muchas operaciones → SDK .NET
  • Script ad-hoc / cross-platform → Web API

Importante: antes de usar cualquier API, el catálogo debe estar set up en el entorno. Es un paso de admin one-time.

06

Claude Code + Power Platform Catalog

5 min

🤖 Lo que Claude aporta encima del catálogo

El catálogo resuelve la distribución. Lo que Claude resuelve es todo el trabajo previo y posterior: empaquetar bien, documentar, versionar, hacer audits antes de publicar, y elegir qué item del catálogo encaja con la necesidad real.

  • Genera la documentación del item a partir del código
  • Genera el release notes entre versiones
  • Hace una auditoría de seguridad antes de submit
  • Consulta el catálogo y recomienda items existentes antes de que el maker reinvente la rueda

📝 Empaquetar y publicar con Claude

Empaqueta la solución LitoCleanTimeTracker, genera un README con descripción, versión, dependencias y screenshots, y prepara el comando pac catalog submit con los metadatos correctos. La versión es 1.2.0 y los cambios principales son los que hay en los últimos 5 commits.

🔍 Buscar antes de construir

Necesito un componente de validación de IBAN para Canvas. Antes de construir, mira si hay algo en el catálogo del tenant. Dame las opciones disponibles, sus versiones y autores. Si no hay nada, propón un plan para construirlo.

✅ Audit pre-submit

Voy a publicar la solución LitoCleanCore al catálogo. Audítala antes: 1) busca secretos hardcodeados, 2) verifica que hay README y CHANGELOG, 3) confirma que todos los componentes tienen prefix pfx_, 4) lista las dependencias externas. Marca en rojo lo que no pase.

📊 Reportes de adopción

Conéctate al CoE Starter Kit y dime: cuáles son los 5 items del catálogo más instalados, en qué entornos, y qué autores son los más activos. Genera un reporte ejecutivo de 1 página para Luis.
