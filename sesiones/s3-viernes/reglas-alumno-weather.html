Sesión 3 — Miércoles

Construye tu Weather App con Claude

Tu primera app real con Claude Code. En 2 horas pasas de carpeta vacía a una app de clima funcionando en tu navegador, con datos reales de cualquier ciudad del mundo.

Objetivo de hoy: al final de la sesión tendrás localhost:5173 abierto en tu navegador con tu propia weather app, buscando ciudades reales y mostrando el clima de los próximos 7 días.
SETUP

Antes de empezar

10 min

Abre la terminal en VS Code (Ctrl + ñ o Ctrl + ´). Sustituye NOMBRE por tu nombre en kebab-case (igual que tu carpeta en /alumnos/).

# 1. Asegúrate de estar en main actualizada
git switch main
git pull

# 2. Crea tu rama de trabajo
git switch -c feature/weather-NOMBRE

# 3. Crea la carpeta de tu app y métete dentro
mkdir -p alumnos/NOMBRE/weather-report
cd alumnos/NOMBRE/weather-report

# 4. Verifica que estás en el sitio correcto
pwd
⚠ Trampa típica: si te saltas el cd, Claude generará archivos en la raíz del repo y romperá cosas. Antes de pegar el P1, repítete: "estoy DENTRO de alumnos/MI-NOMBRE/weather-report".

Ahora abre Claude Code en esta carpeta (Cmd/Ctrl + Esc dentro de VS Code). Estás listo para el P1.

P1

Crear la app con datos de prueba

30 min

Vamos a crear el proyecto Vite + React de cero, con todos los componentes y datos hardcodeados de 3 ciudades (Madrid, Barcelona, Buenos Aires). Aún no tocamos APIs reales.

P1

Scaffold + componentes + mocks

Crea una aplicación React + Vite llamada "weather-report" en la carpeta actual. Estructura: - src/App.jsx, src/main.jsx, src/App.css - src/components/SearchBar.jsx, WeatherCard.jsx, ForecastList.jsx - src/api/weather.js con función getWeatherByCity(city) que devuelve datos hardcodeados para tres ciudades: Madrid, Barcelona, Buenos Aires - package.json, vite.config.js, index.html, README.md corto en español Cada ciudad mock debe devolver: nombre, país, temperatura actual, descripción del clima, humedad, velocidad del viento, y un array de 7 días con día, máxima, mínima y código de clima. App.jsx muestra un SearchBar arriba, debajo el WeatherCard con la ciudad seleccionada, y abajo el ForecastList con los 7 días. Estado inicial: Madrid. Reglas duras: - No ejecutes npm install, lo lanzo yo - JavaScript plano, NO TypeScript - CSS plano, NO Tailwind ni librerías de UI - README en español, máximo 30 líneas

Después de pegar P1

  • Claude crea archivos. Acéptalos uno a uno o "Yes to all".
  • Cuando termine, en terminal: npm install y luego npm run dev.
  • Abre http://localhost:5173 → deberías ver la app con Madrid pintado.
  • Prueba escribir "Barcelona" y "Buenos Aires" en el buscador.
Si algo falla: dile a Claude el error exacto que ves en la terminal o en el navegador. Pega la captura o el texto. No reinventes la rueda — Claude debugea mejor con el error literal delante.
P2

Conectar a la API real (Open-Meteo)

40 min

Sustituimos los mocks por llamadas reales a Open-Meteo. Sin API key, sin registro. Después del P2 podrás buscar cualquier ciudad del mundo.

P2

Reemplazar mocks por Open-Meteo

Modifica src/api/weather.js para sustituir los datos hardcodeados por llamadas reales a Open-Meteo. Usa fetch nativo del navegador (NO axios, NO librerías HTTP). Implementa tres funciones: 1) geocodeCity(name) - llama a https://geocoding-api.open-meteo.com/v1/search?name={name}&count=1&language=es&format=json. Devuelve {lat, lon, country, displayName} o lanza Error("Ciudad no encontrada") si results está vacío. 2) getWeather(lat, lon) - llama a https://api.open-meteo.com/v1/forecast?latitude={lat}&longitude={lon}¤t_weather=true&daily=temperature_2m_max,temperature_2m_min,weathercode&timezone=auto. Devuelve los datos crudos de la API. 3) getWeatherByCity(city) - orquesta las dos anteriores y devuelve un objeto normalizado con la misma forma que tenían los mocks: {city, country, temperature, description, humidity, windspeed, forecast: [{day, max, min, code}]}. Mapea el weathercode a una descripción en español (soleado, parcialmente nublado, nublado, lluvia ligera, lluvia, tormenta, nieve, niebla...). Crea un objeto WEATHER_CODES con el mapeo. App.jsx debe seguir funcionando igual: estado inicial buscar "Madrid", manejar loading y error. Si la búsqueda falla, mostrar el mensaje de error al usuario. Reglas duras: - fetch nativo, sin axios - Sin variables de entorno (.env), todas las URLs van directas - Si geocoding no devuelve resultados, lanza Error("Ciudad no encontrada")

Después de pegar P2

  • Recarga el navegador. Madrid debería seguir mostrándose, pero ahora con datos reales.
  • Prueba "Tokio", "Reykjavik", "Buenos Aires" — todas deben funcionar.
  • Prueba "Asdfgh" — debe mostrar "Ciudad no encontrada".
⚠ Si ves CORS error: probablemente Claude metió la URL mal o intentó usar un proxy. Dile "Open-Meteo permite CORS desde el navegador, llama a la URL directamente con fetch".
P3

Pulido: estados, errores y forecast 7 días

40 min

La app pasa de "demo cruda" a "se ve presentable". Estados de carga visibles, errores claros, forecast semanal con emoji por clima, y CSS legible en móvil.

P3

UX, errores, forecast pintado

Mejora la weather app con los siguientes cambios: 1) Estado de carga: mientras getWeatherByCity está pendiente, muestra "Cargando..." con un spinner CSS simple o texto pulsante. El SearchBar debe deshabilitarse durante la carga. 2) Estado de error: si la llamada falla, muestra el mensaje de error en una caja roja con un botón "Reintentar" que vuelva a llamar a la última ciudad buscada. 3) ForecastList completa: pinta los 7 días en una fila horizontal (en móvil, grid 2 columnas). Cada día muestra: - Día de la semana en español abreviado (Lun, Mar, Mié, Jue, Vie, Sáb, Dom) - Emoji según el weathercode (☀️ soleado, ⛅ parcial, ☁️ nublado, 🌧️ lluvia, ⛈️ tormenta, ❄️ nieve, 🌫️ niebla) - Temperatura máxima y mínima 4) Búsqueda automática inicial: al cargar la página, busca "Madrid" automáticamente (ya estaba, pero asegúrate de que use la API real, no mocks). 5) CSS mejorado: - WeatherCard centrada con max-width 500px - Tipografía clara, contrastes suficientes - Responsive: en pantallas <600px todo debe verse bien apilado - Mantén CSS plano (sin Tailwind, sin styled-components) 6) README actualizado en español: cómo correr la app, qué API usa, estructura de carpetas. Reglas duras: - Sin localStorage, sin geolocalización del navegador (lo dejamos fuera) - Sin librerías HTTP nuevas - Sin librerías de iconos (los emojis van en el JSX directo)

Después de pegar P3

  • Al recargar ves "Cargando..." brevemente, luego Madrid con su forecast.
  • Buscas una ciudad inexistente → caja roja con botón Reintentar.
  • Forecast muestra 7 días con emojis y temperaturas.
  • Reduces el ancho de la ventana → todo sigue legible.
CIERRE

Commit y PR

15 min

Cuando tu app funcione, commitea y abre PR.

# Vuelve a la raíz del repo
cd ../../..

# Verifica qué vas a commitear
git status

# Añade y commitea
git add alumnos/NOMBRE/weather-report
git commit -m "feat(NOMBRE): weather app con Open-Meteo"

# Sube tu rama y abre PR
git push -u origin HEAD
gh pr create --fill
⚠ Antes de commitear: revisa que node_modules/ NO esté en el commit. Si aparece, añade node_modules/ a tu .gitignore dentro de la carpeta de la app.
SOS

Si algo no funciona

SíntomaQué hacer
npm: command not found Necesitas Node.js instalado. Avisa a Yeriel — instalación de Node se hace fuera de esta sesión.
Pantalla en blanco en localhost:5173 Abre la consola del navegador (F12 → Console). Copia el error y pégalo a Claude.
"Failed to fetch" / CORS Verifica que la URL sea https://api.open-meteo.com (no http). Si insiste, díselo a Claude con el mensaje exacto.
Claude generó archivos en la raíz del repo Para todo. Borra los archivos sueltos. Vuelve a hacer cd alumnos/TU-NOMBRE/weather-report. Repite el P1.
"Ciudad no encontrada" siempre Open-Meteo Geocoding entiende español pero a veces falla con tildes. Prueba "Madrid", "Tokyo", "London".
El forecast no aparece Revisa que daily tenga los tres parámetros en la URL: temperature_2m_max,temperature_2m_min,weathercode.
Vas atrasado y solo llegaste a P2 No pasa nada. Una app que pinta clima real es ya un éxito. Commitea lo que tengas.
+

Retos opcionales (si terminas pronto)

  • Geolocalización: al cargar, pedir permiso al navegador y mostrar el clima de tu ubicación actual en vez de Madrid.
  • Última ciudad: guardar la última ciudad buscada en localStorage y usarla al recargar.
  • Modo oscuro: toggle entre claro/oscuro con CSS variables.
  • Unidades: botón para cambiar entre °C y °F.

Para cualquiera de estos, abre Claude y describe lo que quieres. No copies un prompt nuevo entero — itera sobre lo que ya tienes.
