Comandos de Claude Code

Comandos del terminal para la CLI de Claude Code — no del chat de claude.ai. Los 26 oficiales agrupados por categoría, más una sección extra de comandos de review y análisis que te ayudan a mejorar lo que ya has escrito.

01Session Control 6 comandos

Gestionar el ciclo de vida de tu conversación: limpiar, retomar, ramificar, retroceder, renombrar y exportar.

historia
/clear
Limpia el historial de la conversación actual y arranca de cero sin perder el contexto del repo.
reanudar
/resume
Retoma una sesión previa exactamente donde la dejaste, con todo el contexto cargado.
ramificar
/branch
Crea una conversación nueva a partir del punto actual — útil para explorar caminos sin perder el principal.
deshacer
/rewind
Retrocede a un punto anterior de la conversación. Perfecto cuando Claude se ha ido por una mala vía.
organizar
/rename
Renombra la sesión actual para encontrarla más tarde por un nombre descriptivo.
exportar
/export
Exporta los datos de la conversación — práctico para documentar, compartir o auditar lo que se hizo.
Tip de uso: usa /clear entre tareas grandes en la misma sesión. Mantiene el coste bajo sin perder el repo. Reserva /resume para retomar al día siguiente.

02Model & Usage 4 comandos

Saber qué modelo estás usando y cuánto te está costando — clave para no llevarte sustos a final de mes.

modelo
/model
Muestra o cambia el modelo Claude activo (Opus, Sonnet, Haiku).
coste
/cost
Estima el coste de la sesión actual en dólares. Buen reflejo en directo del peso de cada prompt.
resumen
/usage
Resumen del uso del modelo y coste agregado.
detalle
/extra-usage
Desglose detallado del consumo: tokens de entrada, salida, cache, herramientas.
Por qué importa: en sesiones largas Opus puede costar 10-20× más que Haiku. Cambiar a /model haiku para tareas mecánicas (renombrar, mover, formatear) ahorra mucho sin perder calidad.

03Project Setup 4 comandos

Cómo Claude conoce tu proyecto: inicialización, memoria, directorios extra y configuración.

inicializar
/init
Inicializa Claude Code en el directorio actual y genera un CLAUDE.md base con la documentación del repo.
memoria
/memory
Configura o consulta la memoria del proyecto (instrucciones persistentes que Claude recuerda entre sesiones).
directorios
/add-dir
Indexa directorios adicionales fuera del workspace actual — útil para repos múltiples o monorepos.
config
/config
Ver o actualizar ajustes de configuración (tema, modelo por defecto, hooks, permisos).

04Code Operations 5 comandos

Trabajar directamente con el código: ver cambios, revisar seguridad, planificar, gestionar permisos y comprimir contexto.

cambios
/diff
Muestra los cambios actuales respecto al codebase. Como un git diff consciente de la sesión.
seguridad
/security-review
Lanza un análisis de seguridad sobre el código — busca secrets, OWASP top 10, malas prácticas.
planificar
/plan
Genera un plan estructurado para una tarea o proyecto antes de tocar código.
permisos
/permissions
Gestiona qué archivos puede leer y escribir Claude. Clave para repos con datos sensibles.
contexto
/compact
Comprime el contexto de la sesión liberando memoria sin perder lo importante. Antídoto al "context window full".
Combo útil: /plan antes de empezar, /diff para revisar lo hecho, /security-review antes del PR. Tres comandos que evitan el 80% de los problemas en producción.

05Agent Layer 5 comandos

La capa donde Claude se extiende: agentes especializados, skills, plugins y MCP servers.

agentes
/agents
Lista los agentes especializados disponibles (revisores, generadores, auditores...).
skills
/skills
Ver o gestionar las skills cargadas — capacidades específicas que Claude puede invocar bajo demanda.
plugins
/plugin
Gestiona los plugins del sistema (instalar, listar, configurar).
recargar
/reload-plugins
Recarga los plugins instalados sin reiniciar la sesión. Útil tras editar uno.
integración
/mcp
Integración con Model Context Protocol — conecta Claude a sistemas externos (Jira, Notion, Supabase, M365).
El salto de productividad real está aquí: una vez tienes 3-4 skills tuyas y 2-3 MCP servers conectados a tus sistemas, Claude deja de ser un asistente genérico y se convierte en un colega que conoce tu stack.

06Interface 2 comandos

Personalización visual de la terminal — pequeños detalles que mejoran sesiones largas.

tema
/theme
Cambia el tema de la interfaz del terminal (claro, oscuro, alto contraste).
colores
/color
Modifica el esquema de colores del terminal.
Recordatorio importante: todos estos comandos viven dentro del terminal de Claude Code, no en el chat de claude.ai. Si escribes /init en la web, no pasa nada.

07Review & análisis 5 comandos

Los comandos que la cheat sheet no cubre y que en realidad usas más en el día a día: pedirle a Claude que revise lo que ya está hecho y te diga qué mejorar. Algunos son built-in, otros vienen de plugins o skills instalados.

PR review
/review
Revisa una pull request o los cambios de la rama actual: calidad, claridad, bugs potenciales y sugerencias concretas de mejora. El más usado.
cloud
/ultrareview
Review multi-agente en cloud sobre la rama actual o un PR de GitHub. Varios agentes revisan en paralelo y consolidan hallazgos. Lo lanza el usuario, no Claude — y consume créditos.
seguridad
/security-review
Análisis de seguridad: secrets expuestos, OWASP top 10, malas prácticas. Más estrecho que /review pero crítico antes de un deploy.
simplificar
/simplify
Revisa el código que has cambiado buscando reuso, calidad y eficiencia, y arregla lo que detecte. Útil después de una sesión larga donde acumulas duplicación sin querer.
permisos
/fewer-permission-prompts
Escanea tus transcripciones y propone una allowlist de comandos read-only (Bash, MCP) en .claude/settings.json para que Claude pregunte menos. No revisa código, pero mejora cómo trabajas.
¿Cuál uso cuándo? Para el día a día, /review. Antes de mergear a main, /security-review. Para una auditoría profunda de una rama compleja, /ultrareview. Después de horas escribiendo código rápido, /simplify para que Claude limpie lo obvio.
Truco: si no quieres usar un comando, dentro de cualquier sesión normal puedes pedírselo a Claude con un prompt como "hazme una auditoría completa de los cambios de esta rama: tabla con prioridad, hallazgo, impacto, refactor sugerido y esfuerzo". Es el patrón del Prompt 12 de la guía Time Tracker.
