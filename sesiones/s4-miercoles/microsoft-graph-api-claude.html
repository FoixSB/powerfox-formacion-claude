01

Qué es Microsoft Graph y por qué importa

La idea base

Microsoft Graph es una única API REST unificada que expone los datos y la inteligencia de Microsoft 365: usuarios, grupos, correo, calendario, archivos, chats, equipos, tareas, notas, dispositivos, identidades de Entra ID y señales de productividad.

Antes de Graph cada producto tenía su propia API (EWS para Outlook, CSOM para SharePoint, Skype API…). Hoy todo entra por https://graph.microsoft.com/v1.0/ con un único token de Entra ID.

Por qué te importa como integrador

  • Es lo que hay debajo de Power Automate. Cada conector de Office 365, Teams, SharePoint o Planner es Graph envuelto. Si entiendes Graph, entiendes los conectores.
  • Cubre huecos del low-code. Donde el conector estándar no llega (filtros complejos, batch, delta), Graph sí llega.
  • Es portable. Lo mismo que llamas desde Power Automate lo puedes llamar desde Python, Node, C#, Postman o Claude Code.
  • Es la base del MCP de M365. El servidor MCP que ya tienes activado expone Graph como tools usables por Claude.

Una frase para recordar: "Si está en M365, está en Graph". Mail, archivos, calendarios, equipos, listas, libros de Excel, planes, contactos, presencias, reuniones y grabaciones — todo se lee y se modifica por la misma API.

Anatomía de Graph — endpoints, versiones, recursos

Forma de las URLs

// Estructura general https://graph.microsoft.com/{version}/{recurso}?{query} // Ejemplos reales GET /v1.0/me GET /v1.0/me/messages?$top=10&$select=subject,from POST /v1.0/me/sendMail GET /v1.0/sites/root/lists GET /v1.0/teams/{id}/channels GET /v1.0/users/{upn}/drive/root/children

Dos versiones — v1.0 y beta

  • v1.0 — estable, soportado en producción, contrato versionado.
  • beta — funcionalidad nueva, sin garantías. Útil para prototipos pero nunca para producción crítica.

Regla práctica: empieza siempre con /v1.0/. Solo salta a /beta/ si el campo o endpoint que necesitas no existe en v1.0 y puedes asumir el riesgo.

03

Autenticación, scopes y permisos

Toda llamada a Graph va con un access token emitido por Entra ID (antes Azure AD). El token codifica quién hace la llamada y qué le está permitido. La elección de tipo de permiso determina qué puedes hacer y cómo se monta la integración.

Delegated permissions

La app actúa en nombre de un usuario. El usuario inicia sesión y consiente. Es lo que ocurre con los conectores Office 365 de Power Automate y con los MCP de M365 que usas en Claude Code.

  • Sirve para apps interactivas, asistentes, Power Automate, Outlook add-ins.
  • Solo accede a datos a los que ese usuario ya puede acceder.
  • Scopes ejemplo: Mail.Read, Calendars.ReadWrite, Files.ReadWrite.

Application permissions

La app actúa como ella misma sin usuario presente. Requiere consentimiento de un admin global. Es lo que necesitas para servicios desatendidos, jobs nocturnos, integraciones backend.

  • Sirve para daemons, ETLs, integraciones server-to-server.
  • Por defecto ve todo el tenant — peligroso si no aplicas Application Access Policies.
  • Scopes ejemplo: Mail.Read, Sites.Selected, User.Read.All.

Trampa frecuente: registrar una app con permiso Mail.Read Application — eso te da acceso al correo de toda la organización. Para limitarlo a un buzón concreto se usan Application Access Policies. Para SharePoint se usa Sites.Selected.

04

Los 4 caminos para hablar con Graph

No hay un único "camino correcto" para llamar a Graph — hay cuatro perfiles típicos, cada uno con un sweet spot. Lo más potente suele ser combinarlos: Claude Code para diseñar y validar, Power Automate para orquestar, una API externa para batch pesado, y HTTP directo cuando el conector se queda corto.

CAMINO 1

Power Automate — conectores Office 365

Standard, sin coste extra si tienes M365

  • Cuándo: automatizaciones interactivas, aprobaciones, notificaciones, pequeñas integraciones entre apps M365.
  • Pros: visual, low-code, mantenimiento delegable a equipos no-dev.
  • Contras: los conectores cubren ~70% de Graph. Casos avanzados (batch, delta, custom filtering) los limita.
  • Tip: cuando un conector no expone el campo que necesitas, salta al camino 2 (HTTP directo).
CAMINO 2

Power Automate — HTTP a Graph

Premium · acción "HTTP" o "Send an HTTP request to Microsoft 365 / SharePoint"

  • Cuándo: el conector se queda corto y necesitas el endpoint exacto, batch, o una query OData a medida.
  • Pros: 100% de la superficie de Graph desde un flujo low-code.
  • Contras: requiere licencia Premium y registrar la app o usar conexión Microsoft Graph.
  • Tip: "Send an HTTP request to SharePoint" usa el contexto del usuario sin app registrada — útil para cosas SharePoint-only.
CAMINO 3

API externa — Python / Node / C# / Postman

Backend, scripts, jobs, ETL, prototipos

  • Cuándo: cargas grandes, jobs programados, integración con tu propia API, prototipos rápidos.
  • Pros: control total, retries, logging, gestión de tokens fina.
  • Contras: mantienes tú el código, las credenciales y los certificados.
  • Tip: usa los SDK oficiales (msgraph-sdk para Python, @microsoft/microsoft-graph-client para Node) — gestionan el token, paginación y batch por ti.
CAMINO 4

Claude Code — MCP de M365

Asistente que descubre, ejecuta y razona sobre Graph

  • Cuándo: exploración, análisis ad-hoc, diseño de flujos, conversaciones tipo "léeme los últimos 20 mails y resúmemelos por proyecto".
  • Pros: traduce intención de negocio en llamadas Graph correctas, encadena varias en una sesión, te explica los resultados.
  • Contras: no es un job programado — es un canal interactivo. Para algo recurrente, lo usas para diseñar y luego pasas el flujo a Power Automate o a un script.
  • Tip: deja que Claude prototipe la query OData; luego copia esa misma query a Power Automate o Postman.

06

OData — los superpoderes de la query

Graph habla OData. Eso quiere decir que cualquier GET de colección admite una serie de query parameters que te ahorran filtrar, paginar, ordenar y proyectar en el cliente. Es la diferencia entre traerte 500 mails y filtrar en Power Automate (lento, gasta cuota) o pedirle a Graph los 5 que importan (instantáneo).

ParámetroQué haceEjemplo
$selectDevuelve solo los campos pedidos$select=subject,from,receivedDateTime
$filterFiltra registros por condición$filter=receivedDateTime ge 2026-05-01T00:00:00Z
$orderbyOrdena resultados$orderby=receivedDateTime desc
$top / $skipPaginación$top=25&$skip=50
$expandTrae relaciones embebidas$expand=attachments
$searchBúsqueda full-text (KQL)$search="from:cliente AND factura"
$countDevuelve total de coincidencias$count=true
// Los 10 mails más recientes con adjuntos, solo 4 campos GET /v1.0/me/messages ?$top=10 &$select=subject,from,receivedDateTime,hasAttachments &$filter=hasAttachments eq true &$orderby=receivedDateTime desc // Eventos de calendario de la próxima semana GET /v1.0/me/calendarView ?startDateTime=2026-05-12T00:00:00Z &endDateTime=2026-05-19T00:00:00Z &$select=subject,start,end,attendees // Items de una lista de SharePoint con expand de campos GET /v1.0/sites/{site-id}/lists/{list-id}/items ?$expand=fields($select=Title,Estado,Prioridad) &$filter=fields/Estado eq 'Abierto' &$top=50

Detalle de Graph que sorprende: no puedes combinar $filter y $search en la misma llamada. Y algunos $filter sobre /users o /groups requieren la cabecera ConsistencyLevel: eventual + $count=true.

07

Patrones avanzados — batch, delta y cambios en tiempo real

Batch — 20 llamadas en una

El endpoint /$batch agrupa hasta 20 requests en una sola petición HTTP. Reduce drásticamente la latencia y el consumo de cuota cuando necesitas pedir varios recursos a la vez.

POST /v1.0/$batch { "requests": [ { "id":"1", "method":"GET", "url":"/me" }, { "id":"2", "method":"GET", "url":"/me/messages?$top=5" }, { "id":"3", "method":"GET", "url":"/me/events?$top=5" } ] }

Delta — solo lo que cambió

En vez de releer toda una colección, /delta te devuelve únicamente lo que cambió desde tu última llamada gracias a un delta token. Ideal para sincronización incremental.

  • Disponible en mail, calendar, drive, sharepoint, users, groups.
  • Primera llamada = full snapshot + token. Siguientes = solo deltas.
  • Reduce de minutos a segundos los jobs de "qué cambió hoy".

Change notifications (webhooks)

En lugar de polling, Graph empuja eventos a tu endpoint con POST /subscriptions. Cuando algo cambia, recibes una notificación.

  • Cubre mail, calendar, drive, lists, chats, presencias.
  • Caduca cada pocas horas o días — hay que renovar.
  • Rich notifications llevan el payload encriptado.

Cuándo usar cuál: Batch cuando necesitas N cosas ahora. Delta cuando ejecutas un job periódicamente y solo quieres lo nuevo. Webhooks cuando necesitas reaccionar en tiempo real a un cambio sin malgastar peticiones de polling.

08

Claude Code + MCP de M365 — el atajo definitivo

Lo que cambia cuando Claude habla Graph por ti

El servidor ms365 que ya está enchufado en este entorno expone cientos de tools que envuelven Graph: list-mail-messages, create-calendar-event, send-channel-message, create-planner-task, get-excel-range, search-onedrive-files, graph-batch, etc.

Eso significa que no tienes que escribir las URLs ni gestionar tokens. Le pides a Claude lo que quieres en lenguaje natural y él elige el tool, lo invoca, paginá si hace falta y te devuelve la respuesta razonada.

  • Exploración — "Lista los 10 últimos mails con adjuntos PDF y dime de qué proyecto son".
  • Acción puntual — "Crea una reunión mañana 10:00 con Foix y Renny y manda invitación".
  • Análisis cruzado — "Cruza las tareas de Planner del proyecto X con las horas en mi calendario y avísame de huecos".
  • Generación de flujos — "Diseña la query OData que me pediría los archivos modificados esta semana en SharePoint y pásamela lista para pegar en Power Automate".

Patrón recomendado — diseñar con Claude, ejecutar en producción

A

Claude Code prototipa la query, Power Automate la ejecuta a diario

Combo recomendado
  1. Conversación con Claude: "Quiero los items de la lista 'Incidencias' de SharePoint que llevan más de 5 días sin tocar y son de prioridad alta. Pásame el endpoint y la query OData exactos."
  2. Claude responde con el endpoint /sites/{id}/lists/{id}/items?$expand=fields&$filter=... y te lo prueba en vivo con el MCP para validar el resultado.
  3. Pegas la URL en una acción Send an HTTP request to SharePoint en Power Automate.
  4. Programación: trigger Recurrence diaria + envío a Teams del resumen.
  5. Iteración: si mañana cambia el criterio, vuelves a Claude, ajustas la query, copias y pegas. Sin tocar el resto del flujo.

Por qué funciona: Claude es brutal diseñando filtros OData y validándolos contra datos reales. Power Automate es brutal ejecutando en horario y con permisos del tenant. Cada uno hace lo que hace mejor.

B

Análisis cruzado en una sola sesión sin tocar Power Automate

Sesión interactiva

Hay tareas que no compensa programar — son ad-hoc. Para esas, Claude + Graph es directamente la herramienta:

  • "Mira mi calendario de la semana, identifica reuniones sin agenda en el cuerpo y prepárame una propuesta de agenda para cada una."
  • "Saca de Planner las tareas vencidas de mi equipo y mándame un resumen al chat de Teams del proyecto."

Estos análisis serían un flujo de Power Automate de 30+ acciones. En Claude Code son 1-2 prompts y 5 minutos.

Trampas habituales y cosas que se aprenden a base de golpes

Throttling

Graph aplica límites por aplicación, por usuario y por servicio. Si los pasas, devuelve 429 Too Many Requests con un header Retry-After.

  • Implementa retries con backoff exponencial — no machaques.
  • Usa $select para reducir payload y $batch para reducir número de llamadas.
  • Para SharePoint y Outlook hay límites por buzón / sitio que escalan rápido.

Paginación

Graph rara vez devuelve todo en una llamada. Cuando hay más, devuelve @odata.nextLink al final.

  • Repite GET sobre nextLink hasta que desaparezca.
  • Los SDK oficiales lo hacen por ti — los conectores HTTP de Power Automate no.
  • Si solo quieres N, usa $top=N y olvídate del paginado.

Permisos vs scope reales

Que tu app tenga Mail.Read no significa que el usuario haya consentido. La primera vez que llamas, si falta consentimiento, el token te dará 403.

  • Distingue permisos configurados (en el portal) de permisos consentidos (por usuario/admin).
  • Para Application: revisa que el admin haya hecho "Grant admin consent".

Tipos de IDs que importan

Graph mezcla varios identificadores. No los confundas:

  • userPrincipalName (email-like) y id (GUID) — ambos sirven en /users/{id}.
  • siteId tiene formato {hostname},{spsite-guid},{spweb-guid} — no es un GUID simple.
  • Los messageId son largos, base64 y dependen del buzón.

Tres consejos que ahorran horas:

1) Antes de pegarte con $filter, pruébalo en Graph Explorer (developer.microsoft.com/graph/graph-explorer) — autenticado con tu cuenta y con la respuesta JSON visible en pantalla.

2) Cuando un conector estándar de Power Automate devuelve campos vacíos o falta info, el endpoint Graph equivalente casi siempre los expone. Salta a HTTP.

3) Para reuniones, transcripciones y grabaciones de Teams hay endpoints específicos en /communications/onlineMeetings y /users/{id}/onlineMeetings/{id}/transcripts — son joya pura para automatizaciones de productividad.

10

Cierre — qué hacer mañana mismo

Tarea de 30 minutos: abre Graph Explorer con tu cuenta, ejecuta tres llamadas (/me, /me/messages?$top=5&$select=subject,from, /me/events?$top=5) y observa cómo cambia la respuesta cuando metes $select o $filter. Luego replica la misma query desde un flujo de Power Automate con HTTP. En esa hora ya entiendes el 80% del valor de Graph.

Y mientras tanto en Claude Code: abre una sesión y dile "lista mis 5 últimos mails con adjuntos y dime el remitente". Eso ejecuta una llamada Graph real desde el MCP. Cuando funcione, ya tienes prueba viva de los cuatro caminos en menos de una jornada.
