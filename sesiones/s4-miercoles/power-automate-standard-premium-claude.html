Power Automate — Standard, Premium y Claude Code

Diferencias reales entre licencias, qué conectores entran en cada plan, ejemplos prácticos de flujos Standard que puedes montar hoy mismo y cómo usar Claude Code para leer, debuggear y rediseñar flujos desde su JSON.

⏱ Material de referencia · 8 secciones · 5 ejemplos prácticos
01

Qué es Power Automate y para qué sirve

🔄 La idea base

Power Automate es la herramienta de automatización low-code de Microsoft. Permite encadenar acciones entre servicios mediante triggers (algo pasa) y acciones (entonces haz X).

Bajo el capó cada flujo es JSON: una definición declarativa con triggers, actions, connectionReferences y parameters. Eso es justo lo que vamos a aprovechar más adelante con Claude Code.

🧩 Tres tipos de flujos

  • Cloud flows: automáticos (trigger), instantáneos (botón) o programados.
  • Desktop flows (RPA): grabación de UI, requiere licencia Premium.
  • Business process flows: guías visuales en Model-Driven Apps.

💡 El 90% del valor en empresas medianas está en los cloud flows. Es por donde recomendamos empezar.

02

Standard vs Premium — La gran diferencia

La línea divisoria principal en Power Automate no es la potencia del motor — es a qué conectores tienes acceso y cuántas ejecuciones puedes hacer. Todo el resto del producto (triggers, condicionales, bucles, scopes) está disponible en ambos planes.

STANDARD

Power Automate Standard

Incluido en tu licencia Microsoft 365 (E3, E5, Business Premium...)

  • Conectores estándar: Outlook, SharePoint, OneDrive, Teams, Forms, Planner, Excel Online, OneNote, Power BI
  • Cloud flows automáticos, instantáneos y programados
  • Aprobaciones integradas en Teams y Outlook
  • Hasta 6.000 acciones / usuario / día (Microsoft 365)
  • Sin coste adicional si ya tienes M365
PREMIUM

Power Automate Premium

~15 $/usuario/mes o ~100 $/flujo/mes (per-flow plan)

  • Todos los conectores Premium: Dataverse, SQL Server, HTTP, Custom Connectors, ServiceNow, Salesforce, SAP, Oracle…
  • Conector HTTP genérico (cualquier API REST)
  • RPA (Desktop flows) con o sin asistente
  • AI Builder (incluye créditos)
  • Process Mining y Hosted Machines

⚠️ Trampa habitual: usar el conector Dataverse en un flujo "Standard" lo convierte automáticamente en Premium. La solución no se podrá importar en un entorno donde los usuarios no tengan licencia Premium. Microsoft te avisa con un icono de diamante 💎 en cada acción premium.

04

Limitaciones reales del plan Standard

🚫 Lo que NO puedes hacer en Standard

  • Llamar a APIs REST genéricas (no hay conector HTTP)
  • Leer/escribir en Dataverse (tablas custom)
  • Conectar a SQL Server, Oracle, MySQL on-prem
  • Usar AI Builder (form processing, prediction…)
  • Crear Custom Connectors
  • RPA (automatización de UI de escritorio)

📊 Cuotas y límites diarios

PlanAcciones/díaFrecuencia mín. trigger
M365 Standard6.000 / usuario5 min

💡 Las acciones en bucles (Apply to each) cuentan cada iteración. Un flujo con 100 elementos × 5 acciones = 500 ejecuciones contra tu cuota.

05

5 Ejemplos prácticos con Power Automate Standard

Todos estos flujos se montan con conectores incluidos en cualquier licencia M365. Cero coste extra. Tiempo medio de implementación: 15–30 min cada uno.

1

Backup automático de adjuntos de Outlook → OneDrive

Standard

Caso de uso: archivar facturas, contratos o partes de trabajo que llegan por email sin que el usuario tenga que descargar nada.

  1. Trigger: Outlook · When a new email arrives (V3) filtrado por carpeta o asunto
  2. Condición: "Has Attachments = true" para evitar ejecuciones vacías
  3. Apply to each sobre Attachments
  4. Acción: OneDrive · Create file en una carpeta organizada por año/mes con formatDateTime(utcNow(),'yyyy/MM')
  5. Acción opcional: Outlook · Mark as read + mover a carpeta "Procesados"

💡 Filtra con "Importance" = High o un asunto regex para evitar archivar spam. La cuota Standard se gasta rápido si no filtras.

2

Formulario interno → Email + canal de Teams

Standard

Caso de uso: solicitudes internas (acceso, hardware, vacaciones, incidencias) sin pasar por correo manual.

  1. Trigger: Forms · When a new response is submitted
  2. Acción: Forms · Get response details
  3. Acción: Office 365 Users · Get manager (V2) del solicitante
  4. Acción: Outlook · Send an email (V2) al manager con plantilla HTML
  5. Acción: Teams · Post message in a chat or channel en el canal del equipo

🎯 Multiplica por 10 la velocidad de respuesta de RR. HH. o IT comparado con un buzón compartido. Se monta en 20 min.

3

Aprobación de gasto sobre lista de SharePoint

Standard

Caso de uso: el equipo apunta gastos pendientes en una SharePoint List; los superiores a 500 € requieren aprobación del manager.

  1. Trigger: SharePoint · When an item is created
  2. Condición: Amount > 500
  3. Acción: Approvals · Start and wait for an approval (tipo Approve/Reject)
  4. Switch sobre outcome:
    • Approve: SharePoint · Update item con estado "Aprobado" + email al solicitante
    • Reject: SharePoint · Update item con motivo + email

⚠️ Las aprobaciones tienen 30 días de timeout por defecto. Si nadie responde, el flujo expira. Configura recordatorios o reasignación.

4

Resumen diario de tareas Planner pendientes → Teams

Standard

Caso de uso: cada mañana a las 8:30 cada miembro del equipo recibe en su chat de Teams un resumen de tareas Planner asignadas con vencimiento en los próximos 7 días.

  1. Trigger: Schedule · Recurrence (días laborables 8:30)
  2. Acción: Planner · List my tasks filtradas por dueDateTime < addDays(utcNow(),7)
  3. Compose: construir Adaptive Card con la lista en HTML/Markdown
  4. Acción: Teams · Post adaptive card in a chat with Flow bot

💡 Variante: en vez de Planner usa To Do (también Standard) para tareas personales. Mismo patrón.

5

Onboarding: nuevo empleado → kit completo

Standard

Caso de uso: cuando RR. HH. añade una fila en la SharePoint List "Altas", se dispara una cadena de bienvenida automática.

  1. Trigger: SharePoint · When an item is created en la lista "Altas"
  2. Acción: OneDrive · Copy file de la carpeta "Plantillas onboarding" a una carpeta personal del nuevo empleado
  3. Acción: Outlook · Send email con el welcome pack al manager
  4. Acción: Planner · Create a task "Completar onboarding {{nombre}}" asignada al manager
  5. Acción: Teams · Post message en el canal #bienvenidas

🎯 Sustituye un proceso típicamente de 4 personas y 6 emails por un flujo de 12 acciones que tarda 2 segundos.

Power Automate Tool — Claude Code lee tu flujo en JSON

La idea: cada flujo es un JSON que Claude Code puede entender

Cuando exportas un flujo desde Power Automate (Solución → Exportar como ZIP → descomprimir), dentro encuentras workflow/[guid]/definition.json con la estructura completa: triggers, acciones, condiciones, expresiones de Power FX y referencias a conexiones.

Eso permite usar Claude Code como un copiloto que entiende tu flujo a nivel código: te lo explica, te lo refactoriza, te lo migra, te lo documenta o te genera uno nuevo desde requisitos.

📂 Cómo localizar el JSON

  1. En make.powerautomate.com abre la Solución que contiene el flujo
  2. Exportar > Exportar como no administrada → descarga un .zip
  3. Descomprime localmente. La estructura es: Workflows/[NombreFlujo]-[GUID].json
  4. Cada flujo tiene su clientdata con la definición completa en $schema y actions

⚠️ El flujo debe estar dentro de una solución, no en "Mis flujos". Si está fuera, primero añádelo a una solución.

🧠 Qué le puedes pedir a Claude Code

  • Auditoría: detectar conectores Premium ocultos, conexiones hardcodeadas, secretos en claro
  • Documentación: generar un README explicando el flujo paso a paso
  • Migración: reemplazar referencias de un entorno DEV → PROD
  • Refactor: dividir un flujo gigante (>50 acciones) en child flows
  • Generación: a partir de un texto de requisitos, producir un JSON que importes directamente

🔍 Anatomía de un flujo en JSON (ejemplo simplificado)

{
  "properties": {
    "connectionReferences": {
      "shared_office365": {
        "connection": { "connectionReferenceLogicalName": "new_outlookConnRef" },
        "api": { "name": "shared_office365" }
      }
    },
    "definition": {
      "$schema": "https://schema.management.azure.com/.../workflowdefinition.json#",
      "triggers": {
        "When_a_new_email_arrives": {
          "type": "OpenApiConnectionWebhook",
          "inputs": { "parameters": { "importance": "High" } }
        }
      },
      "actions": {
        "Apply_to_each_attachment": {
          "type": "Foreach",
          "foreach": "@triggerOutputs()?['body/attachments']",
          "actions": {
            "Create_file": {
              "type": "OpenApiConnection",
              "inputs": {
                "parameters": {
                  "folderPath": "/BackupOutlook/@{formatDateTime(utcNow(),'yyyy/MM')}",
                  "name": "@{items('Apply_to_each_attachment')?['name']}"
                }
              }
            }
          }
        }
      }
    }
  }
}

Este JSON es el ejemplo nº 1 (backup de adjuntos) en su forma exportada. Claude Code puede leerlo, validarlo y proponerte añadir un Scope de Try/Catch sin que abras Power Automate.

⚡ Prompts útiles para esta workflow

@auditar-flujo
Lee el archivo Workflows/MiFlujo-XXX.json.

1. Lista todas las acciones y su tipo de conector (Standard / Premium).
2. Marca cualquier valor hardcodeado que debería ser Environment Variable
   (URLs, IDs de SharePoint, emails de cuenta de servicio).
3. Detecta si falta manejo de errores (Scope con runAfter "Failed").
4. Resume el propósito del flujo en 3 líneas.
@migrar-entorno
Tengo el flujo exportado de DEV en Workflows/Onboarding.json.
Necesito una versión para PROD donde:

- La SharePoint Site URL pase de https://dev.sharepoint.com/sites/RRHH-DEV
  a https://prod.sharepoint.com/sites/RRHH
- Los IDs de listas se sustituyan por los de PROD (los tienes en prod-ids.json)
- Las connection references usen los nombres con sufijo _prod

Genera el JSON modificado y un diff de cambios.
@flujo-desde-requisitos
Genera el JSON de un cloud flow Standard que:

1. Se dispare cuando se cree un item en la lista SharePoint "Solicitudes"
2. Si el campo "Importe" > 500, lance una aprobación al manager del solicitante
3. Si se aprueba, actualice el item a estado "Aprobado" y envíe email
4. Si se rechaza, actualice a "Rechazado" con el motivo

Usa solo conectores Standard. Devuelve el JSON listo para importar
dentro de una solución (formato Workflows/[name].json).

💡 Truco: guarda estos prompts como slash commands en .claude/commands/ del repo del equipo y los reutilizas con /auditar-flujo Workflows/MiFlujo.json.

07

Casos donde Claude Code aporta más valor

📚 Documentar flujos legacy

Tienes 40 flujos heredados sin documentación. Pasas la carpeta Workflows/ a Claude Code y le pides un README por flujo + un índice maestro. 2 horas vs 2 semanas.

🔁 Migración masiva DEV → PROD

Un cambio de tenant o un rename de site. En vez de tocar manualmente las acciones en cada flujo, Claude Code hace search & replace estructural sobre el JSON y devuelve el ZIP listo para importar.

🛡️ Auditoría de gobernanza

Detectar flujos con conexiones a cuentas personales, secretos hardcodeados, conectores Premium en escenarios no autorizados. Claude Code escanea el JSON y genera un reporte por carpeta.

🧬 Refactor a child flows

Un flujo con 80 acciones es inmantenible. Claude Code propone los 4-5 sub-flujos en los que dividirlo y genera el JSON tanto del padre como de los hijos.

⚠️ No es magia. Claude Code te genera JSON válido de cloud flows pero los desktop flows (RPA) usan un formato XAML diferente y mucho más opaco. Para esos, usa Claude Code para documentar pero no para generar.

08

Takeaways

  • Standard cubre el 80% de las automatizaciones internas de una organización M365. Antes de pedir Premium, revisa si lo que necesitas se hace con Outlook, SharePoint, Teams, Forms y Planner.
  • Premium = conectores externos + IA + RPA. Si tu flujo toca Dataverse, SQL externo, una API REST cualquiera o necesita extracción de PDFs, te toca Premium.
  • El icono diamante 💎 en cualquier acción es la señal inequívoca de Premium. Si lo ves, mira si hay alternativa Standard.
  • Los flujos son JSON y eso desbloquea todo el potencial de Claude Code: auditar, refactorizar, migrar entornos, generar desde requisitos.
  • Workflow recomendado: exportar solución → abrir JSON en VS Code → trabajar con Claude Code → re-importar. Mucho más rápido que el editor visual cuando el flujo tiene muchas acciones.
