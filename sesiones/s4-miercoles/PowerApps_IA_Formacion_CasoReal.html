Antes de escribir una línea

Lo que nadie te cuenta en los demos de 5 minutos

Sin esta preparación, la IA trabaja a ciegas e inventa nombres de tablas y campos que no existen. El 80% del éxito está aquí.

🔧 PAC CLI

Exportar soluciones, pac solution unpack para XML editables, pac canvas unpack para convertir .msapp en YAML. Claude Code lo ejecuta directamente.

🔍 Dataverse DevTools

Extensión de VS Code para navegar metadata (tablas, columnas, relaciones, option sets) sin salir del editor. Manual: el desarrollador consulta y pasa los display names reales al prompt.

📦 Power Platform Extensions

Pack/Unpack de Canvas App: .msapp ↔ carpeta YAML. Sin esto Claude Code no puede leer las pantallas existentes y no respeta patrones, temas ni naming conventions.

🔐 Autenticación (DeviceCode)

Scripts Python usan DeviceCodeCredential. No InteractiveBrowser porque cuelga en Git Bash/WSL. Token expira a la hora → get_token() antes de cada request.

⚠️ Lección aprendida: InteractiveBrowserCredential cuelga en terminales no interactivos (Git Bash, WSL, terminal embebida de Claude Code). Se descubrió por la vía dura gastando 2-3 iteraciones. Ahora vive como regla en la memoria del proyecto.

Skills y repos de referencia configurados

  • Microsoft Dataverse-skills (github.com/microsoft/Dataverse-skills): 3 SKILL.md para creación de tablas, export/import, conexión. Aporta: creación por fases con espera 15-30s, header MSCRM.SolutionUniqueName, código idioma 3082 (es-ES).
  • Skill custom canvas-apps-ui-gen: genera YAML en formato "bare" (empieza por - controlName:) apto para pegar en PA Studio. Sin este skill, la IA genera formato Screens: que da error PA1001.
  • Knowledge base centralizada del equipo: guías sobre PAC CLI, Power Automate, ribbons, referenciadas desde el CLAUDE.md del repo.

Pros y Contras honestos

✅ Pros

  • Ahorro 60-70% en tiempo total — de 2 semanas a 3 sesiones
  • Backend casi perfecto a la primera — tablas, lookups, vistas, sitemap con mínimo retrabajo
  • Documentación automática de altísima calidad — specs, handoffs, checklists de testing, manuales de flujo. Antes tardabas horas, ahora minutos
  • Los docs generados sirven para que el cliente testee solo — menos reuniones de soporte, el cliente sigue los flujos paso a paso
  • Coste en tokens ridículo — $9-14 todo el proyecto
  • Memoria reutilizable — los errores descubiertos se guardan y las próximas sesiones los heredan
  • Mockups HTML antes de desarrollar — el cliente valida visualmente antes de invertir horas
  • Scripts Python masivos — crear 44 campos uno a uno en la UI es tortura; con un script son 2 horas

❌ Contras

  • Canvas App YAML nunca pega limpio — siempre requiere Find & Replace + ajustes manuales
  • ~15 categorías de errores recurrentes de pegado que tienes que aprender
  • La IA genera código sintácticamente correcto pero funcionalmente incorrecto — bugs silenciosos que solo detectas al probar
  • Preparación previa necesaria — PAC CLI, DeviceCode, unpack, skills. 2-3 horas antes de pedir nada
  • Context window se "diluye" — tras ~30 mensajes la IA olvida decisiones tomadas al principio
  • Handoffs entre sesiones = re-explicar contexto — 3-6 veces por sesión
  • Layouts pixel-perfect imposibles — alineación, spacing, z-index hay que hacerlo a mano
  • Requiere desarrollador que domine Power Fx — sin experiencia, generas basura que no puedes arreglar
Los errores que cuestan horas

Pain Points reales del YAML + Canvas App

Estas son las ~15 categorías de error que descubrimos. Cada una costó iteraciones. Ahora viven en la memoria del proyecto para no repetirlas.

Display Names

La IA inventa nombres de datasource

Genera 'Lineas de Secado' (sin acento) cuando PA Studio usa 'Líneas de Secado'. Cada datasource mal = error "not found" al pegar.

Screens: wrapper

Formato YAML incorrecto para paste

El formato Screens: de pac unpack NO funciona para la función "Paste code" de PA Studio. Hay que usar formato bare: - controlName:

Modern Controls

Propiedades inválidas

[email protected] no acepta Size:, Icon: (string), BorderColor:. [email protected] rechaza Format:. Hay que cambiarlos en la UI manualmente.

Dos puntos en strings

YAML se rompe con ":" dentro de valores

Placeholder: ="Buscar ej: A12591" → YAML lo parsea como key-value y revienta. Hay que quitar los dos puntos o usar literal block.

Jerarquía containers

Paste al padre equivocado

PA Studio pega los controles al elemento seleccionado. Si seleccionas un Rectangle en vez del GroupContainer, el paste falla silenciosamente.

Versiones de control

[email protected] no existe

La IA inventa versiones de controles. [email protected] no existe — usar @2.3.0. Hay que mantener una tabla de versiones válidas.

OptionSet column ≠ valor

La regla más confusa de Power Fx

Columna: 'Estado (xxx_estado)'. Valor: 'Estado (Líneas de Secado)'.'En Secado'. No son el mismo nombre. Y hay excepciones sin regla universal.

Filter compara objetos

Compila pero devuelve 0 registros

Filter(Tabla, Lookup = _record) compila pero compara objetos completos. Fix: usar Lookup.'Campo (schema)' = _record.'Campo (schema)'.

Variables sin tipar

Set(var, Blank()) peta 3 pantallas después

Set(_var, Blank()) no tipa la variable. Usar Set(_var, LookUp(DataSource, false)) que nunca devuelve nada pero tipa correctamente.

Campo primario ambiguo

record.Nombre vs record.'Nombre (schema)'

Si el campo primario se llama igual que la tabla, PA exige schema name: 'Secado (xxx_secadoid)' para ID, 'Secado (xxx_secadoname)' para display.

Colecciones vacías

Clear(col) falla en primera carga

Clear(col) en una colección que no existe da error. Fix: ClearCollect(col, {ID: GUID()}); Remove(col, First(col)) para tipar + vaciar.

Nombres históricos

.Unidades vs .Filas

La IA genera .Unidades pero el campo real se llama .Filas por decisión histórica del cliente. Solo se descubre al probar con datos reales.

Ventana de contexto

Tras ~30 mensajes la IA "olvida"

En el chunk 6, la IA sugirió 4 sondas cuando la spec decía 5 (aire, caldera, madera 1/2/3). La info se "diluyó" tras 30 mensajes.

Re-explicaciones

3-6 veces por sesión

Hay que re-explicar decisiones ya tomadas en la spec o en handoffs previos. Cada re-explicación son 1-2 mensajes extra que rompen el flow.

Handoffs entre sesiones

4 documentos de 120-270 líneas

Sin los handoffs, cada sesión nueva reinventa nombres de campos. En un experimento temprano la IA sugirió un nombre completamente diferente al acordado.

Guía práctica

Qué delegar y qué NO delegar a la IA

Esta es la guía que se llevan a casa. Basada 100% en experiencia real de este proyecto.

🟢 Delegar con los ojos cerrados

  • Creación de tablas Dataverse (scripts Python vía Web API)
  • Generación de specs desde transcripciones
  • Vistas XML para Model-Driven App
  • Documentación (handoffs, checklists, READMEs)
  • Scripts de automatización PAC CLI
  • Mockups HTML del layout

🟡 Delegar con supervisión

  • YAML de Canvas App (con tabla Find & Replace)
  • Fórmulas Power Fx complejas
  • Dashboards Model-Driven
  • Power Automate flows (JSON)

🔴 NO delegar

  • Layouts pixel-perfect
  • Containers anidados en galleries
  • Cambios de Format, Icon, Theme en UI
  • Lógica de estado runtime
  • Decisiones de UX

Valor oculto

Documentación generada: el superpoder que nadie menciona

La IA no solo escribe código. Los documentos que genera aceleran demos, reducen reuniones de soporte y permiten que el cliente testee por su cuenta.

📋 Manual de Flujos de Procesos

HTML visual con 8 flujos paso a paso, cajas de decisión en los puntos de validación, badges de estados. El cliente lo abre en el navegador y sigue los pasos como un tutorial. Antes tardabas 6-8 horas en escribir esto. Con IA: 30 minutos.

✅ Checklist de Testing Interactivo

16 casos de prueba con checkboxes clickables. El cliente marca lo que ya probó. Incluye: qué probar, qué resultado esperar, qué hacer si falla. El cliente testea solo sin necesitar una reunión de 2 horas.

🖼️ Mockup HTML Interactivo

Antes de desarrollar nada, se genera un mockup visual de la pantalla maestro-detalle. El cliente valida la disposición de campos, botones y modales. Evita el "no era lo que esperaba" post-desarrollo.

📝 Spec Funcional + Handoffs

402 líneas de spec funcional + 4 handoffs entre sesiones. La spec es el "contrato" que evita malentendidos. Los handoffs garantizan continuidad entre sesiones de Claude Code sin perder contexto.

Impacto real: Estos documentos no son "nice to have". Son los que permiten que el cliente haga sus propias pruebas, que la demo sea fluida, y que si otro desarrollador entra al proyecto no empiece de cero. La IA los genera en minutos con la información correcta del proyecto.
La pregunta difícil

¿Se puede hacer sin saber Power Apps?

Respuesta honesta: No.

La IA multiplica por 2-3× a un desarrollador experto. Al principiante lo pone a generar código roto que no puede arreglar — coste negativo, frustración alta.

No sabes que una tabla tiene un prefijo xxx_srr_ distinto de xxx_stt_ y por qué. La IA te sugiere nombres que suenan bien pero no existen en el entorno. No puedes validar si los lookups apuntan a la tabla correcta.
No detectas que Filter(Tabla, Lookup = _record) compila pero devuelve 0 registros. No sabes que hay que comparar por ID con schema name. Los bugs silenciosos te destrozan.
No sabes que Format: no se puede cambiar en YAML con modern controls. No distingues los controles @0.0.45 de los clásicos. No entiendes por qué el paste falla y piensas que la IA miente.
Desarrollador con 1-2 años de experiencia en Power Platform que quiere acelerarse. Conoce Dataverse, ha publicado Canvas Apps, domina Power Fx lo suficiente para oler problemas. La IA es su copiloto, no su piloto.

Preguntas frecuentes

Q&A preparado

Suscripción Claude Max ~$100-200/mes cubre este volumen sin problema. En pago por uso, este proyecto entero costó ~$9-14 en tokens. El coste real no son los tokens — es la hora del desarrollador que supervisa. Mil veces más caro que los tokens, mil veces más valioso.
Mejor con Model-Driven. Model-Driven es XML estructurado (Entity.xml, SavedQueries, RibbonDiff) que la IA genera muy bien. Canvas App tiene la complejidad extra del YAML propietario + Power Fx + quirks de los modern controls. En este proyecto, todo el backend Model-Driven fue ~2h perfecto; la Canvas App fue ~12h al 90%.
Copilot es excelente para generar un primer draft de una pantalla sencilla dentro del Studio. Lo que NO hace: trabajar con el repo fuera del Studio, versionar con git, razonar sobre múltiples pantallas a la vez, generar scripts Python para crear 44 campos en lote, escribir specs de 400 líneas, mantener memoria del proyecto entre sesiones. Claude Code complementa a Copilot; no compite con él.
Pasó durante este proyecto — el versionado de modern controls es frágil. La mitigación: la memoria del proyecto se actualiza cada vez que descubrimos un nuevo caso. La regla no vive en la cabeza del desarrollador, vive en archivos versionados. Si Microsoft cambia algo, actualizas la memoria y todas las sesiones futuras lo heredan.
Sí para leerlas — la IA lee Entity.xml sin problema. No para modificarlas — las soluciones managed son read-only por diseño de Power Platform. Para personalizar sobre una managed, se crea una solución unmanaged propia encima que haga extensión.
Para llevarse a casa

10 recomendaciones

  1. Invierte 1-2h en preparación (PAC CLI, auth, unpack). Sin esto, cualquier ahorro de IA queda anulado.
  2. Escribe la spec ANTES de tocar código. 400 líneas de spec ahorran 40 horas de desarrollo.
  3. Usa handoffs con fecha entre sesiones. Cada sesión lee el anterior para reanudar contexto.
  4. Mantén una memoria viva de los pain points. Cada descubrimiento va a un archivo versionado.
  5. Divide la Canvas App en chunks lógicos. Chunks más grandes = debugging más caro.
  6. Reserva 20% del tiempo para correcciones manuales post-paste.
  7. Pasa el display name exacto de cada datasource en el prompt.
  8. Pide el diff antes de aplicar — evita el refactor sorpresa.
  9. Si hay deadline, usa lo que dominas. Canvas App es el camino conocido.
  10. Documenta qué NO funcionó. La negativa es igual de valiosa que la positiva.
